[2026-08-25 09:12] Completed: Ran the system live end-to-end for the first time (`CHAT_PROVIDER=ollama`, `llama3.1:8b` chat + `nomic-embed-text` embeddings, local Postgres+pgvector) and produced `EVAL_CASES.md` with 15 consult-note test cases (note, full response, correctness assessment). Fixed four real bugs surfaced only by a live run: (1) `PgVectorStore` requires `Document.id` to be a UUID — ingestion used human-readable ids like `"catalog:1A00"`, now a deterministic UUID derived from the natural key with the readable id kept in metadata; (2) Spring Boot 4.1.1 doesn't auto-configure a classic Jackson 2 `ObjectMapper` bean (defaults to Jackson 3) — added one explicitly in `JacksonConfig`; (3) `@Lob` on `CodingAuditLog.iterationsJson` mapped to Postgres `oid` instead of `text`, making the audit trail unreadable via SQL — switched to `columnDefinition = "text"`; (4) worked around two pre-existing, unrelated local services occupying ports 5432 (native Postgres) and 8080 (Apache) by moving our Postgres container to 5433 and the app to 8081, without touching either existing service. Eval result: 288 catalog entries + 31 guidelines ingested correctly; retrieval and the proposal agent performed well in all 15 cases (correct evidence retrieved and correctly cited every time, zero wrong/hallucinated codes); but the verification agent under `llama3.1:8b` was unreliable, causing 7/15 cases to fail safe (`NO_CONFIDENT_MATCH`) despite strong on-point evidence — a model-quality issue specific to the small local chat model, not the architecture. Recommend re-running with `CHAT_PROVIDER=anthropic` for a real accuracy read.
